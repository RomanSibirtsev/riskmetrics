# Риск-метрики: веб-MVP

Этот пакет содержит веб-MVP для анализа портфеля из облигаций, найденных на MOEX. Основной интерфейс рассчитывает 1-дневные VaR/ES на 99%, Key Rate DV01 по 12 узлам и CS01 по историческим данным MOEX ISS с полной переоценкой денежных потоков. Учебный синтетический API задания сохранён отдельно, но больше не используется в пользовательском интерфейсе.

## Ограничения

- Основной калькулятор использует найденные реальные выпуски MOEX; рыночную стоимость и направление каждой позиции пользователь задаёт сам.
- В сохранённом наборе 517 общих торговых дат (01.10.2024–12.10.2026), 2 068 котировок четырёх выпусков, закрывающие параметры G-кривой и полные купонные графики.
- VaR/ES ограничены 500 однодневными историческими сценариями. Пропущенные в старых строках значения ZSPREAD восстанавливаются из закрывающей цены, G-кривой и будущих денежных потоков; опубликованные значения MOEX используются напрямую и калибруют восстановленный ряд.
- KRD содержит 12 теноров от 3 месяцев до 30 лет. CS01 отображается для корпоративных выпусков; к ОФЗ он не применяется.
- Текущие котировки могут поступать live через Finam Trade API при настройке локального секрета `FINAM_SECRET`. Сценарии VaR/ES и кривая ставок остаются архивными данными MOEX; это не live-обновление всех риск-факторов.
- Последние доступные рыночные цены сохраняются из Finam и MOEX ISS. Если свежего тика нет, расчёт использует последнюю сохранённую внешнюю цену; при её отсутствии — последнее дневное закрытие MOEX. Источник и timestamp видны рядом с выпуском.
- В интерфейсе можно найти облигацию по ISIN в MOEX ISS. После добавления приложение загружает историю котировок, G-кривую и график денежных потоков; для выпуска с неподдерживаемой офертой или короткой историей покажет причину отказа.
- Архивные записи также можно синхронизировать через `POST /api/v1/market-data/moex/sync`; статус и объём хранимых данных доступны через `GET /api/v1/market-data/moex`.
- Архивные методы ISS могут требовать подписку/права доступа. При отказе API возвращает ошибку `moex_unavailable`; данные не подменяются синтетическими значениями.
- В `data/moex_risk_history_500.json` хранится основной набор для рыночного калькулятора; небольшой исходный пример оставлен в `data/moex_demo_history_2026-10-01_2026-10-12.json`.
- Все демонстрационные инструменты используют RUB.
- Позиция передаётся как положительная рыночная стоимость; направление `long` или `short` задаётся отдельно.
- Web-интерфейс собирается на React + TypeScript и раздаётся приложением API. Compose публикует порты только на localhost.

## Учебный синтетический API

Сохранённый API задания содержит шесть вымышленных ISIN-подобных идентификаторов `ZZ...`. Они не показываются в интерфейсе и не относятся к реальным ценным бумагам. Веб-интерфейс использует выпуски MOEX ниже.

## Сохранённый снимок MOEX

Файл `data/moex_snapshot_su26207rmfs9.json` — небольшой справочный снимок ОФЗ-ПД 26207 (ISIN `RU000A0JS3W6`, SECID `SU26207RMFS9`) на 12.10.2026. Для рыночного расчёта используется отдельный расширенный набор с полной историей и денежными потоками. G-кривая MOEX описана биржей как параметрическая кривая с непрерывно начисляемыми ставками и дополнительными сглаживающими членами ([методика MOEX](https://www.moex.com/s2532)). Исторические данные ISS могут требовать подписки и договора; в проекте они используются для учебного показа.

## Загрузка истории MOEX

Основной пакет загрузки формируется на компьютере с доступом к MOEX ISS. Загрузчик сохраняет последние 500+ торговых наблюдений, закрытия G-кривой и все страницы coupon/amortization графиков по четырём учебным выпускам:

```powershell
pwsh -NoProfile -ExecutionPolicy Bypass -File .\data\download_moex_risk_history.ps1
docker cp .\data\moex_risk_history_500.json mvp-api-1:/tmp/moex_risk_history_500.json
docker exec mvp-api-1 python -m api.import_moex_dataset /tmp/moex_risk_history_500.json
```

Основной экран **«Риск облигационного портфеля»** принимает выпуски из загруженного набора MOEX, сторону и заданную пользователем рыночную стоимость позиции. API-эквиваленты: `GET /api/v1/market-data/moex/instruments` и `POST /api/v1/risk/moex`.

Историческая переоценка применяет разницу параметрических G-кривых MOEX между соседними датами и ежедневный кредитный spread. Для каждого сценария будущие купоны и погашение переоцениваются заново. KRD показывает изменение стоимости при отдельном повышении узла на 1 б.п.; CS01 — результат повышения Z-spread на 1 б.п. VaR и ES рассчитаны по худшим однодневным сценариям 500-дневного окна, эмпирическим квантилем 99%.

В портфеле используются SU26207RMFS9 (ОФЗ-ПД 26207), RU000A102HC1 (Сбербанк 002СУБ-02R), RU000A103TX0 (ВТБ Б-1-242) и RU000A102879 (ВТБ СУБ-Т2-1). Текущие параметры выпусков и купонные графики запрашиваются из официального ISS bondization.

Если контейнер API имеет выход в интернет, откройте `http://localhost:8000/docs` и выполните `POST /api/v1/market-data/moex/sync`. Пример тела запроса:

```json
{
  "securities": ["SU26207RMFS9"],
  "from_date": "2025-01-01",
  "till_date": "2026-10-12"
}
```

Синхронизация получает дневную историю облигаций и параметры G-кривой на конец торгового дня. Она сохраняет рыночные ряды, но справочные данные и денежные потоки для нового набора выпусков следует дополнить выгрузкой `download_moex_risk_history.ps1` и импортом JSON.

Для чтения исторических данных MOEX может потребоваться действующая подписка. Условия доступа и допустимое использование нужно сверить с [официальной страницей ISS](https://www.moex.com/a2193) и [руководством разработчика](https://www.moex.com/files/4be999zbzp80bx2bgmwayrtyx0). Проект предназначен для учебного показа, выгрузки MOEX не следует отдельно публиковать.

Если Docker не имеет DNS/выхода к MOEX, импортируйте сохранённый пример из корня проекта:

```powershell
docker cp '.\data\moex_demo_history_2026-10-01_2026-10-12.json' mvp-api-1:/tmp/moex_demo_history.json
docker exec mvp-api-1 python -m api.import_moex_dataset /tmp/moex_demo_history.json
```

Импорт можно выполнять повторно: наблюдения обновятся по ключам даты и выпуска, а в журнал добавится новая запись.

## Вход для расчёта

`TradeInput(isin, position_market_value=Decimal("1000000"), side=PositionSide.LONG)`

Функция `calculate_portfolio(trades, catalog)` возвращает результаты по сделкам и портфелю. Числовые значения остаются `Decimal` без округления; форматирование будет задачей API/UI слоя.

## Запуск API и PostgreSQL

Запустите Docker Desktop и дождитесь готовности Docker Engine. Для пересборки UI перейдите в `ui` и выполните `pnpm install --frozen-lockfile`, затем `pnpm build`. Production-сборка хранится в `ui/dist`. Из каталога `mvp` выполните:

```powershell
docker compose up --build
```

После запуска интерфейс доступен на `http://localhost:3000`, API — на `http://localhost:8000`, интерактивная документация — `http://localhost:8000/docs`. API раздаёт собранный UI и обслуживает его запросы с того же origin. Проверки состояния: `GET /healthz` и `GET /readyz`. PostgreSQL хранит историю в Docker volume `risk_metrics_pgdata`; при остановке контейнеров данные сохраняются.

API и PostgreSQL в compose настроены для локальной разработки. Перед размещением в общей сети нужно заменить локальные реквизиты БД и настроить доступ согласно целевой среде.

Основные маршруты и точные форматы описаны в [API-контракте](API-контракт.md). Схема PostgreSQL создаётся при старте приложения из SQLAlchemy metadata.

## Аккаунты и приватность истории

При первом открытии интерфейса зарегистрируйте аккаунт по email и паролю (от 12 символов) или войдите в существующий. Пароли хранятся как Argon2id-хэши; браузер получает HttpOnly cookie, а сервер хранит только хэш случайного идентификатора сессии. Сессия действует 12 часов и отзывается при выходе. Для HTTPS-развёртывания задайте `AUTH_COOKIE_SECURE=true`.

Старый API синтетических расчётов сохраняет историю отдельно для каждого пользователя; прежние записи без владельца не попадают в личные истории. Основной интерфейс и рыночный API используют найденные выпуски MOEX. Справочные инструменты и рыночные данные общие; расчёт MOEX требует входа.

## Live-котировки Finam

Опциональный поток Finam включается переменной `FINAM_SECRET` в локальном корневом `.env`. Скопируйте `.env.example`, добавьте секрет Trade API с разрешением на чтение рынка и выполните `docker compose up --build -d`. Секрет не хранится в БД или UI и не должен попадать в исходный код, Git или чат. Без секрета MVP продолжает работать по архивному MOEX close.

Для расчёта используется последняя сохранённая цена Finam или MOEX вне зависимости от возраста её timestamp. Если внешняя котировка отсутствует, цена берётся из последнего дневного закрытия MOEX. Исторические VaR/ES-сценарии, кривая и купонные денежные потоки остаются данными MOEX на архивную дату. Интерфейс отдельно показывает источник и время цены, а также дату кривой. Перед учебным показом проверьте условия Finam для использования и отображения рыночных данных.
